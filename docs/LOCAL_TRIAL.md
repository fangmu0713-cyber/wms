# 本地试用 · 0.5.0

这是浏览器访问的WMS/OMS/PDA应用。当前交付是源码和本地试用入口，没有公网生产网址。试用时只使用虚构数据；真实客户、真实库存和ERP接入留待正式验收。无需连接GitHub或ERP账号。

Mac用户可以使用带双击入口及两种芯片离线依赖的专用包，详见[MAC_TRIAL.md](MAC_TRIAL.md)。下文是通用命令行入口；Mac专用入口的数据存放在用户Library目录。

## 1. 准备和启动

电脑需安装Python 3.12，并能下载项目锁定的Python依赖。解压源码包，进入有README.md的wms文件夹。Windows建议使用PowerShell：

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.lock
.\.venv\Scripts\python.exe -m scripts.local_trial
```

macOS/Linux：

```bash
python3.12 -m venv .venv
.venv/bin/python -m pip install -r requirements.lock
.venv/bin/python -m scripts.local_trial
```

浏览器打开 http://127.0.0.1:8000 。当前脚本只监听本机，不对局域网或互联网开放。端口被占用时加`--port 8001`，浏览器同步改为8001。按Ctrl+C停止，之后执行同一启动命令可继续，已录数据保留。`--prepare-only`仅准备试用，不启动服务。

脚本忽略WMS_DB_PATH，始终使用独立目录`var/local-trial/`下的`trial.sqlite3`。仅首次建立示例货主、两仓、四库位、一个SKU、已上架100件及待处理3件订单；普通生产启动仍不自动生成示例数据。目录已存在但不属于完整试用时会拒绝，不能覆盖业务库。请勿同时启动两个进程使用同一试用目录。

需全新一轮时，用`--directory var/local-trial-2`创建另一个目录，原数据不删除。原凭证过期/撤销或文件丢失时停止自动续接，不会静默重发凭证或重置库存。

## 2. 登录与岗位切换

在本机编辑器打开`var/local-trial/accounts.token`，找到所需账号的`token`值，复制该值到页面的“访问令牌”框。不要复制引号或整个JSON文件，也不要将文件/令牌发送聊天、提交代码或截图。文件仅在本机生成，POSIX权限0600；Windows应使用本人的受控用户目录，另按本机ACL管理访问。凭证有效30天。

|账号键|用途|范围|
|---|---|---|
|admin|基础资料、管理、审批|本试用租户全部仓库|
|source_picker|拣货、跨仓发出|示例圣保罗仓|
|destination_receiver|分批接收调拨|示例里约仓|
|counter_a|初盘|只读/提交自己的盲盘任务|
|counter_b|独立复盘|只读/提交自己的盲盘任务|

管理员能走完整试用；切换岗位可检查权限是否符合现场分工。退出后重新登录切换账号。刷新浏览器需要重新登录；凭证不会保存在浏览器存储。所有示例SKU条码为`789000000001`，可手动输入模拟键盘扫码；这不代表实物扫码枪、相机或打印机已验收。

## 3. 建议试用顺序

以下数量以全新试用目录为准，按顺序执行。重试未知响应时保持原页面和原请求，不更改数量/批次，不刷新或换人重做。

1. **库存与出库**：admin登录，库存应为圣保罗仓SP-A01的100件。订单管理中找到TRIAL-ORDER-3并预占，PDA页面按条码与SP-A01拣3件、复核3件、填写包裹号打包、填写承运方和运单号实际交接。预占/拣货/打包期间在库仍100，实际出库后97。
2. **跨仓调拨**：admin在跨仓调拨创建从SP-A01到示例里约仓的10件单，填唯一参考号；可分配先减10，在库不变。切source_picker扫码整单发10件，此时源仓在库87、跨仓在途10。切destination_receiver，选RIO-A01接收6件，批次填TRIAL-ARRIVAL-1；再接收4件到RIO-A02，批次TRIAL-ARRIVAL-2。最终源仓87、目标仓10、跨仓在途0，保管实物总量97。每批只有确认合格实际到货才接收；未到或有争议件继续在途。
3. **盲盘与复盘**：admin选择源仓、该SKU、SP-A01、counter_a建盘点单。该库存测量期间暂停作业。切counter_a，任务不应显示账面数量。为了演练差异，可用虚构读数86（与步骤2账87相差−1）；提交后解除测量暂停，但短少1件锁定不可售。admin分配counter_b复盘；切counter_b填86。两账号的差额一致后，admin填原因审批，源仓变86；目标仓10，合计96。此为模拟短少，不能在真实库存中随意套用。若填87则为零差异，不需要复盘。
4. **检查结果**：admin在库存与流水查看余额、订单预占、待搬/调拨锁、盘点锁、两类在途和只追加流水；总览的库存核对应正常。切中葡语言、缩窄浏览器或使用开发者工具的手机视口检查常用操作。

可另建一笔调拨演练在途丢失：先实际发出，可分批接收一部分，剩余量保留在途。只有admin根据确认丢失依据填写全部剩余数量与原因结案。结案后不允许再登记这笔的到货；找回、争议、赔偿和残次品处置的完整流程尚未实现。不要用丢失结案代替未查清的异常。

## 4. 怎样提修改意见

记录“使用账号/岗位、页面、操作步骤、预期结果、实际结果”，有截图可附页面局部，隐藏令牌及个人/客户资料。优先反馈：页面名称是否符合仓库习惯、扫码步骤是否多余、必填字段是否合适、岗位能否完成本职工作、手机操作是否顺手。卡住时保留报错原文和单号，不重复造单掩盖问题。

## 已验证与当前边界

本版本已验证真实临时SQLite/HTTP/Chromium业务流程；证据见evidence/stage5。Windows/macOS安装步骤尚未在这两类实机验证。当前仍为单节点SQLite、API凭证登录、全量快照；不是完整生产安全或容量验收。没有ERP真实连接、物流面单、实物设备、离线持久队列或生产部署。跨仓只支持同货主/单SKU/单来源库位、整单发出、分批合格接收与管理员确认在途丢失；无跨货主转移、部分发出、撤销丢失、调拨退回或残次品接收区。
