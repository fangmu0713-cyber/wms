# DECISIONS

- D001 2026-10-16：仓库为空，首阶段采用已有运行环境中的 Python/FastAPI + SQLite，避免依赖外部基础设施。单节点本地持久卷，BEGIN IMMEDIATE 串行化写事务；高吞吐多节点 PostgreSQL 迁移为后续任务，不能将本阶段称为大规模生产方案。
- D002：总控独占 schema/迁移/API 契约，子任务仅写各自目录，集成前核对契约。阶段一见 CONTRACT.md。
- D003：收货/质检记录与可售库位库存分离；上架才增加可售实物库存。预占/拣货/复核/打包不重复扣实物，交接出库才扣一次。退货收货且质检上架后增加库存。
- D004：Bearer token 仅保存 SHA-256 摘要，服务端租户、货主和仓库权限。变更必须有幂等键；不同请求复用键报错；按货主/店铺唯一外部订单号。
- D005：取消只支持未拣货订单；拣货后取消需实体归位流程，后续实现；已出库只能经退货流程。
- D006：中葡界面、BRL 整分记账；ERP provider 全部待接入，内部 API 与服务商 API/卖家自用 API 明确区分。
- D007：`on_hand` 表示合格已上架库位库存；待检、合格未上架与残次实物按单据状态另记，`stock_summary.physical_total` 汇总实际保管总量。退货通知不计入实物；残次未做报废前仍在保管。UI 展示质量分区，不能把物理总量当作可售。
- D008：本环境 Docker build 网络无法解析依赖源；获授权下载固定版本 wheels 到忽略目录 wheelhouse，Dockerfile 支持 WMS_OFFLINE=1 离线安装。基础镜像固定已拉取 digest；不修改宿主 DNS/代理/网络。
- D009：首阶段用 30 天可撤销 API 凭证登录，CLI 在本机受控边界签发。密码、MFA/SSO、审批、在线凭证轮换、CLI管理操作完整审计尚未实现，是正式生产启用前的安全验收项；不能宣称完整身份平台。
- D010：未知浏览器响应锁定原提交，保留原请求/幂等键后重试；业务成功与 UI 数据刷新失败分开提示。刷新页面会丢失内存状态，跨重载的持久客户端待提交队列尚未实现。
- D011：本轮环境重置到初始README；从原上传bundle恢复a2681d4，阶段2的a0a955d对象不在环境中，按本聊天重建002波次及操作页面，并重新跑31项恢复回归。保留来源事实，不把重建代码声称为找回旧commit。
- D012：同货主同仓显式选择已预占未拣订单建波次，逐订单分配独立任务，库位/SKU/订单字典序路线；领任务的人才能扫码，零实拣可释放，活动波次禁止旧pick绕过。波次完成仅拣货完成。
- D013：003同仓人工补货/移位采用“待搬锁定→实际搬出→目标实际到位”。move_reserved独立于订单reserved，所有预占路径扣除搬运锁。已搬出数量用任务/账本in_transit显式保管，不能瞬间同时出现在两个库位，也不能被可售。
- D014：同仓移动整任务收发，未搬出可取消，搬出后禁止取消/换人/部分接收；异常不伪造接收解除。自动补货、损耗/回位和跨仓调拨另建模型。physical_total在D007基础上新增同仓in_transit；核对同时检查库存、订单分配、待搬锁和逐任务搬运中。
- D015：库内新表单与中葡文案放warehouse-config.js声明配置，复用原真实API表单/内存幂等重试；不另建模拟前端。本轮准备独立远程分支与草稿PR防临时环境重置；是否成功以远程证据为准，不自动合并或部署。
- D016：004盘点采用单货主/单仓/单SKU显式库位范围。每轮测量同事务记录账面和ledger rowid截点并持久锁定库存，提交即释放测量锁。所选库存有订单/搬运占用时先处理原作业；其他库存仍可继续。snapshot对测量暂停余额显示count_locked=true/available=0。
- D017：独立复盘比较各自截点的差额，不能比较不同时间的总读数。首盘零差额可确认，非零须最近两次不同账号差额一致。已知短少取历次最大值锁count_reserved，后续正常作业扣除此锁。审批仅增减差额，不覆盖余额，释放短少锁与调整同事务。
- D018：新增count_only凭证作用域而非改8角色CHECK。只能作为picker由CLI明确签发；认证后每条API强制路由限制，snapshot/GET/幂等响应均不返回账面/截点/差额或他人读数。主管与admin审批独立于盘点凭证；不同账号不等于已核验不同现实人员。
- D019：取消保留观察/审计、释放暂停和差异锁，不代表差异已解决。004无down；旧0.3不执行count_only边界和盘点锁，不能直接降级。旧001/002/003字节不改，本轮更新原草稿PR，不合并或部署生产。

- D020：005跨仓采用单货主/单SKU/单源库存的独立调拨单，复用move_reserved作为未发出占用；只增ledger.transfer_transit_delta/transfer_lost_delta，不把跨仓和同仓in_transit混合。整单发出、逐批实际合格到货、确认在途丢失结案，未查清不虚报接收或丢失。
- D021：建单/取消主管须两仓授权；发出只需源仓picker/staff，接收只需目标仓receiver/staff，查询需至少一端授权。可见单的双方ID及运单为作业凭据，不开放未授权仓其他库存。缓存重放也重新检查角色/仓权限。
- D022：每批receipt_reference在调拨内唯一并生成不可改删事件，跨人员/键重复同批阻断。跨仓在途按源仓责任归集一次，收到才进入目标；丢失管理员按全部剩余量及原因结案，累计丢失不是实物。暂不提供找回/撤销/残次或赔付流程。
- D023：本地试用使用显式`python -m scripts.local_trial`新建隔离目录及虚构100件/3件待处理订单/五岗账号；不使用WMS_DB_PATH，不在普通生产启动塞种子，不覆盖已有目录或输出令牌。用户晚些本地试用，本轮不启动公网或改外部服务。
