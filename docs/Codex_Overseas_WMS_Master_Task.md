# 海外仓 WMS + 货主 OMS + 官方 ERP 对接中心
## Codex Cloud 总任务书

版本：1.0
官方资料核查日期：2026-10-16
文档性质：开发与验收要求，不是已经开发完成或已经获得 ERP 接入权限的证明。

## 0. 任务目标与边界

请在当前获授权的代码仓库内，开发一套可独立部署、可持续维护的海外仓管理系统。
业务能力参考极风 WMS 的公开官网与帮助中心；采用原创界面、原创实现，不复制其商标、专有代码、登录后素材或受限文档，不绕过登录、付费或接口审批。

目标是“仓库管理端 WMS + 货主/客户端 OMS + 手机/PDA 作业端 + 官方 ERP 对接中心”，不是进销存表格，也不是只有菜单、图表和模拟数字的前端展示。
完整产品分阶段交付。首阶段必须跑通真实数据库支持的业务闭环；其他阶段不得用空页面冒充完成。

默认适配用户的巴西电商业务：简体中文和巴西葡萄牙语、BRL 主币种、可配置仓库时区；同时保留其他国家、语言、币种扩展能力。
TikTok Shop、Shopee、Mercado Livre 是优先服务的业务渠道，不代表已取得这些平台接口权限，也不要求首期分别直连三个平台。
店铺、公司、仓库、货主、税号、收费方式均使用配置，不硬编码用户尚未确认的真实资料。
支持自营仓与对外服务海外仓；货主门户和仓储计费可按经营模式启停。

不要把整个 ERP 重新做一遍：商品刊登、广告投放、全套采购财务与会计申报不是本次默认范围。
本系统重点管理实际库存、仓内作业、履约、仓储收费和跨系统同步。

## 1. 先核实再实施

先检查当前仓库、分支、已有架构、AGENTS.md、依赖版本、测试、数据库迁移、部署配置和已授权环境。不得假设仓库为空，也不得未经说明重写已有业务。

按本任务书末尾的官方来源建立 `docs/reference-matrix.md`：
- 功能名称、参考来源、查询日期、参考事实与本项目设计的区别。
- 本期实现范围、后续范围、验收方式。
- 页面不可读取或需要登录时，记录限制，不猜测隐藏菜单、接口和内部算法。
- 各 ERP 必须再次核查执行当日的官方文档与实际账户权限，旧资料不代替当前合同或接口权限。

开始编码前用简短报告说明架构选择、首个闭环与外部阻塞；随后实际开发，不停留在建议或需求文档。

## 2. 开发组织与可续接要求

采用“总控任务 + 可独立验收子任务”的方式。支持并行时再使用并行，不假设环境一定支持子代理。
总控负责数据库模型、接口契约、权限模型、迁移次序、代码集成和最终验收。
子任务可分为前端、库存与履约、ERP 适配、财务、测试与部署，但必须基于已冻结的契约；不要让多个任务无协调地改同一组数据库迁移。

建立并持续维护：
- `AGENTS.md`：开发、启动、测试、迁移和安全规则。
- `docs/PROJECT_STATUS.md`：已完成、已验证、待验证、外部阻塞、下一步。
- `docs/TASK_BOARD.md`：任务编号、依赖、负责范围、验收状态。
- `docs/HANDOFF.md`：当前分支、变更、测试证据、未完成操作、准确续接步骤。
- `docs/DECISIONS.md`：关键架构和业务口径决策。
- `docs/ERP_CAPABILITIES.md`：逐 ERP、逐接口的能力与权限证据。

任务上下文不足、超时或中断前，优先保存代码和交接信息。后续任务先读这些文件，不从头重写。
需要合并时提交可审查的 PR；未经授权不直接改动生产环境。

## 3. 必须建设的产品模块

### 3.1 组织、货主、仓库与权限

支持多公司/租户、多货主、多仓、多店、多用户，角色包括管理员、仓库主管、收货员、拣货员、打包员、财务、客服、货主只读/操作账号。
采用服务端权限校验与数据范围控制，覆盖页面、API、导出、附件、后台任务、通知与对外接口。
公司租户与货主是不同维度；同一租户下不同货主的库存、订单、报价和账单同样隔离。
租户与授权范围从认证上下文确定，不能相信前端传入的 tenant_id/owner_id。
登录、审批、改价、调库存、重打、导出、密钥变更等记录审计轨迹。
高风险操作使用审批或再次确认；管理员支持加强认证。

### 3.2 商品、SKU 与仓库结构

商品 SPU、SKU、颜色规格、图片、条码别名、尺寸重量、箱规、单位换算、组合装与拆组记录。
SKU 与条码按货主范围管理；同名 SKU 不得误合并不同货主的库存。
维护平台/ERP/店铺 SKU 与内部 SKU 的显式映射，未知 SKU 进入待映射队列，不自动猜配。
仓库层级至少包括库区、巷道/货架、库位；支持收货区、质检区、存储区、拣货区、打包区和异常区。
支持箱号、托盘号，后续可启用批次、序列号、效期。箱/托盘是容器关系，不能和件数重复累计。
组合装要明确“虚拟组合销售”与“实际组装成品”的区别；组件分配和可售计算不得双重占用。
导入支持预检查、重复识别、逐行错误反馈、审计与可控撤销。

### 3.3 入库

入库预报/ASN、到货预约、扫描签收、按件/箱/托盘收货、数量差异、破损与照片、质检、标签打印、上架任务、收货完成。
允许部分到货、分批上架、溢短收货；差异须审批并保留依据。
预报单、采购单或 ERP 通知本身不增加实物库存；必须由实际收货事件入账。
待检、异常、已合格但未可拣和正式可分配库存必须分开，不能刚扫到货就直接允许销售。
货主可查询进度、差异和照片，但只能查看自己的资料。

### 3.4 库存与库内作业

按货主、仓库、SKU、库位、质量状态及启用的批次/序列维度保存库存。
具备在库、可分配、已预占、待检、残次、冻结、在途等明确口径。
维护库存流水、余额投影、预占记录和业务关联，不允许通过普通编辑接口直接改余额。
支持移位、补货、盘点/盲盘、复盘、盘盈盘亏审批、安全库存、库龄与低库存预警。
盘点要定义范围与截点，并处理盘点期间出入库；不得简单覆盖盘点后发生的新流水。
库间调拨分为发出、在途、接收，部分接收和丢损单独处理，不能瞬间同时出现在两仓。
“冻结”是不可分配条件，不等于商品离仓；数量与状态转换应有守恒校验。

### 3.5 订单履约与出库

订单可来自已获授权的 ERP、系统公开 API、Excel/CSV 导入或货主手工创建。
支持校验、去重、缺货挂起、分仓规则、预占、波次、拣货、复核、称重、打包、面单、交接出库、发货回传。
分仓和波次规则先提供可解释的规则与排序，不虚构“AI 最优路线”。
支持单品多件、多品多件、组合 SKU、一个订单多个包裹、部分发货、允许范围内的拆单合单。
订单、订单行、包裹、拣货任务分别建模；部分履约不能误标整单已完成。
不同货主、收件人或不兼容物流/平台规则的订单禁止随意合并。
拣错、漏扫、超量、重复扫描必须阻断或进入有权限的异常处理。
取消规则按实际履约状态执行：未拣可释放；已拣未交接须撤销作业并确认货物回位；已实际出库不能直接凭取消通知恢复库存。

### 3.6 物流、面单与设备

区分平台/ERP 已提供面单与仓库自行购买物流面单；不为平台物流订单重复购买。
记录承运商代码、服务渠道、运单、包裹、尺寸重量、标签版本、交接批次与轨迹。
先支持真实授权来源的面单接收、校验、打印和重打；无权限时只提供明确标注的测试样本。
重打已有面单不新建包裹，不重复计费，不重复申请单号。
支持物流服务商查询、报价与下单的适配扩展，但逐家通过官方接口验证后才启用。
条码枪键盘输入和手机/PDA 大按钮作业为基础；相机扫码、蓝牙/网络打印和电子秤均需单独验证兼容性。
优先交付浏览器打印流程。需要本地打印桥时使用受控认证，不能暴露无鉴权的局域网/公网打印服务。
在浏览器环境无法验证实物设备时，交付测试步骤并明确“待实机验收”，不得宣称设备已打通。
网络不稳定时显示提交状态；断网扫描不得伪装成功，离线待提交和已入账必须可区分。

### 3.7 退货、异常与举证

支持未签收退回、买家退货、无关联退件、退货授权、扫码签收、质检、拍照、重新上架、换标、维修/待处理、报废。
退货通知或退款状态不直接增加可售库存；收货与质检合格后才转换为可分配库存。
无关联退件先隔离，确认归属后再入对应货主账。
破损、少件、多件、错货、丢件、取消拦截失败形成异常工单，可关联费用调整和赔偿依据。
照片与可选视频附件使用私有访问、保留期限与访问审计，不默认无限保存或公开链接。

### 3.8 货主 OMS 门户

货主独立登录，管理自己的商品/映射、入库预报、发货申请、订单、库存、退货、异常、费用、账单、授权与 API 凭证。
可配置货主可见仓库、可用物流、服务报价与账户权限。
提供订单/库存/账单导出、消息提醒、状态查询和常见异常说明。
财务、报价、客户资料不可因搜索、批量导出、附件 URL 或接口 ID 枚举而越权泄露。
不要求货主登录仓库管理员后台来办理日常业务。

### 3.9 财务、计费与对账

支持入库费、出库操作费、首件/续件费、耗材、仓租、退货、换标、附加服务和物流成本。
报价按货主/仓库/服务/生效日期版本化；支持免租期、库龄阶梯、按件/箱/托盘/体积等计费维度。
明确仓租的计量快照、日界线、单位换算及舍入规则；后改报价不追溯污染已确认账单。
费用记录关联实际作业事件，同一个事件和计费项目不得重复收费。
账单草稿、核对、确认、收款登记、调整/冲销、争议、导出流程完整。
余额、授信、欠费预警是可选账务功能；未对接支付机构前，只能登记审核后的收款凭证，不显示自动支付成功。
收入、成本与毛利明确区分“仓储服务经营口径”和“卖家商品销售利润”，不能混用。
BRL 为默认货币，扩展 CNY/USD；不同币种不得直接相加，换算需记录汇率来源、日期和版本。
金额使用精确十进制/最小货币单位，不能依靠二进制浮点进行结算。

### 3.10 高级业务

第二阶段后逐项交付：B2B 大货出库、箱/托盘管理、平台仓补货/FBA 转运、退货换标、多仓调拨、客户分销库存配额。
再扩展：提柜/拆柜/派送任务、跨境直邮、代理仓和复杂货盘分销。
每个启用模块都要有真实数据模型、状态机、权限、流水、异常处理和验收测试。
不在本次已实施范围内的功能应隐藏或明确标注未上线，不能仅放一个可点击菜单就计入完成率。
分销配额是分配规则，不凭空增加物理库存；代理仓库存单独标记来源，不能当作本仓已在库。

### 3.11 报表与运营看板

展示真实数据库汇总：待收货、待上架、待拣、待打包、待交接、超时任务、缺货、异常、库龄、盘点差异、计费/应收和员工工作量。
支持按公司、货主、仓库、店铺、SKU、时间和业务类型筛选并导出。
每个指标写清分子、分母、时间边界和数据来源，时区切换不能改变原始记录。
演示数据必须标记且与真实环境隔离；不得在生产看板写死销售额、利润或业务增长率。
告警至少在系统内可见，外部通知渠道在凭证配置和授权后再启用。

## 4. ERP 对接方案与事实边界

### 4.1 三条路径不可混淆

A. 卖家企业自用 API：访问获授权企业账户的数据。
B. 海外仓服务商接入：让卖家在 ERP 中选择本海外仓并授权、推单。
C. 本系统开放 API：由合作方按本系统文档接入。

A 可用不代表已获 B；完成 C 不代表任何 ERP 会自动接入。
不得把“兼容接口设计”“模拟器通过”“读取一次库存”“获得 token”写成“已经正式对接该 ERP”。
不通过抓网页、逆向私有接口、复制 Cookie、共享账户密码来替代官方生产对接。

### 4.2 核查到的候选 ERP

1. UpSeller：优先核实。
   官方 2026-09-28 指南公开列出的 Open API/MCP 能力是仓库列表和 SKU 库存查询，并列有适用套餐。
   官方 2026-08-28 FAQ 说明：对接对象是海外仓服务商，其他自研系统也属于可使用的系统类型；需以服务商为单位单独对接，属于收费定制服务。
   因此开放 API 读取库存与海外仓推单履约是两条不同路径。
   先实现已验证文档的读取适配及“待商务接入”状态，不捏造订单接收、发货回传和库存写入接口。
   一旦取得服务商协议与技术文档，再完成商品/订单/面单/入库/退货/库存/出库状态等实际授权范围。

2. 店小秘：
   官方已有海外仓授权、仓库/物流渠道映射和平台面单推送流程。
   这些资料证明存在海外仓接入模式，不证明新自研 WMS 可以自行注册后自动出现在授权列表。
   新服务商准入、协议、费用、测试与发布要求需另行从官方确认；目前不得编造通用接入接口。

3. 领星：
   官方提供企业 OpenAPI；接入需要 AppID/AppSecret，并配置公网 IP 白名单。
   按官方实际接口确认商品、库存、自发货/多平台订单、履约回传能力及所需权限。
   不因文档中存在“订单”“海外仓”分类，就推定支持用户全部巴西渠道的完整写入流程。
   不把开发环境临时出口 IP 或本地 IP 当作稳定生产白名单。

4. 马帮：
   官方 OpenAPI 指南要求企业 AppKey、密钥及相应 API 权限。
   当前指引只是入口依据；开始实现时再次核对接口版本、权限、限流和具体订单/库存/履约协议。
   无权限时保留明确的未配置状态，不跳过鉴权。

5. Bling：
   作为巴西本地 ERP 候选扩展。官方提供 REST API、OAuth 2.0 与订单、商品、库存、物流、发票等资源文档。
   逐项核查 OAuth 权限、账户要求、限流、审核和是否适用于本业务。
   企业自用与公开上架的应用要求可能不同；不得默认所有应用都已经获审核。
   库存和订单状态写回必须防止 ERP 因单据状态变更再次扣减同一批库存。

### 4.3 统一适配层

设计 Connector/Adapter 契约，按能力启用：
商品/映射、仓库/渠道、订单接收/查询、入库预报、退货、面单、取消、库存、发货/包裹状态、账单/附件（仅在对方支持时）。
各 ERP 返回结构先转换为内部规范模型，不把供应商特定字段散落到核心库存逻辑。

每家维护：
- 官方文档、核验日期、账户/套餐/服务商准入条件。
- 授权方式、权限范围、环境、限流、回调、分页与增量策略。
- 字段映射、状态映射、库存口径与主数据责任。
- 已实现方法、已测试方法、测试证据、已验证读写范围和外部阻塞。
- 状态：文档待确认 / 待授权 / 模拟测试通过 / 真实只读验证 / 沙箱闭环验证 / 已批准生产启用。

不支持的方法明确返回“不支持”，不能静默成功或返回假数据。

### 4.4 同步可靠性与主从关系

WMS 对本仓实物库存、库位、质检与实际出库负责；ERP/平台负责获授权范围内的销售订单与平台状态。
对每个字段定义唯一责任方与同步方向，禁止双方互相覆盖形成循环或重复扣减。
ERP 库存读数默认用作对账/导入依据，不自动覆盖已运行的 WMS 实物账。

实现持久化 inbox/outbox、队列、幂等键、唯一约束、限流、带退避重试、超时、死信/人工补偿、运行日志和告警。
接收回调要验签/校验授权与防重放（按官方协议），持久保存事件后再确认接收。
分页/增量读取保存游标与时间水位，考虑更新延迟与重叠窗口，靠幂等去重。
乱序消息不得把已完成订单回退；取消、地址变更和发货事件根据版本/状态做冲突判断。
对外提交超时而结果未知时先查询/对账，不盲目重新建单、购面单或扣费。
允许人工修复映射、重放失败任务和对账差异，但都需权限与审计。
建立每日或可配置周期的订单、包裹、库存和计费对账任务。

无第三方凭证时可交付官方协议驱动的契约测试和独立模拟器。模拟环境必须醒目标识，不计为真实 ERP 验收。

## 5. 库存、履约和费用的硬规则

1. 每次库存变动关联业务单据、来源事件、操作者、时间、货主/仓库/SKU 维度及幂等键。
2. 库存账本对普通业务账号只追加不改删；余额与账本在同一事务内一致更新，修正使用冲销/补正事件。
3. 预占使用数据库事务与原子条件/锁，两个并发请求不能同时成功占用最后一件货。
4. 在库数量按已定义的物理位置与质量状态统计；可分配库存以合格且允许拣货的数量为基数，扣除覆盖同一数量口径的预占与安全库存。避免把待检/残次重复扣减。
5. 预占不减少实物在库；拣货/打包是位置或作业状态变化，不再次扣实物；实际交接出库时仅扣一次并清理对应预占。
6. 多包裹、部分发货按订单行和包裹数量过账，不能先扣整单后又按包裹扣一次。
7. 已实际出库后收到取消，不自动加回库存；通过退货收货与质检流程处理。
8. 退货入库、调拨收货、盘点调整、组合拆装都必须有守恒和重复事件测试。
9. 不直接依赖 Redis 中的余额作为库存真相；数据库与账本是持久依据。
10. 费用根据实际事件和报价版本生成，重试、重打、重新展示不重复收费；已确认账单通过调整单更正。
11. 对应缺货、无效 SKU、质检失败、额度不足和外部超时要提供可恢复状态，不能只返回通用“操作失败”。
12. 对关键不变量编写自动化测试；不要用 UI 校验替代服务端与数据库约束。

## 6. 技术、部署与安全

采用成熟、可维护的技术栈，优先复用当前仓库；空仓项目先采用模块化单体，不先拆成大量微服务。
使用关系型数据库、可靠后台任务、私有文件存储、明确的前后端边界；生成并维护 OpenAPI 或等价接口契约。
新依赖检查官方维护状态，固定版本/锁文件。避免引入多个完成同一工作的框架。
数据库必须有迁移、索引、约束与回滚/前向修复方案；测试环境不能冒用生产库。

本项目将 Codex Cloud 用于开发、测试和交付，正式系统单独部署到获授权的长期运行云环境。
交付可复现容器构建、配置模板、健康检查、数据库持久化、worker 启停、日志轮转、HTTPS 配置和部署说明。
缺少服务器/域名/授权时，完成部署包与本地/测试环境验收，将真实上线标记为阻塞；不得伪造可访问网址。

生产环境的数据库、缓存、后台管理端口不直接公开；服务按最小权限访问。
密钥通过当前环境支持的安全配置/密钥管理注入，生产与开发分离；不写入代码、聊天、截图、构建产物或日志。
按实际协议选择安全注入方式，不假设所有需要本地签名的密钥都能由网络代理占位替代。
限制外部请求域名；获取面单或附件 URL 时防止 SSRF、超大文件及恶意内容。
防止越权、SQL 注入、XSS、CSRF、上传滥用、爆破、CSV 公式注入和敏感数据日志泄露。
私有附件采用短期授权访问；API 密钥支持范围、撤销、轮换与访问审计。
涉及巴西税务资料时只做必要字段、附件与已授权合规服务对接；税务规则交专业服务/合格会计确认，不自行硬编码未经核实的开票规则，不把本系统称为已完成税务合规认证。

提供备份、恢复演练、版本发布、升级、回退、告警和管理员操作说明。
在上线前说明可实现的 RPO/RTO 与证据，不写未经测试的 SLA。
不得改动用户现有代理 VPS、SSH、安全组、节点或已运行服务来给本系统腾资源；共用环境改动必须先获明确批准。

## 7. 分阶段实施与验收门槛

### 阶段 0：核实与设计
检查仓库，建立参考与 ERP 权限矩阵，确定数据模型、状态机、库存口径和安全边界。
并行准备 ERP 商务/权限申请清单，但不得自动代表用户签约或付费。
交付可执行任务看板，而不是等待所有第三方审批后才开始建设。

### 阶段 1：基础底座与首个真实闭环
完成登录权限、多货主、多仓、多 SKU、入库、质检、上架、订单、预占、扫描复核、交接出库、库存流水。
由手工/文件/本系统 API 创建订单即可启动，第三方连接未获批不阻塞内部闭环。
完成中文和葡语关键作业页面、数据库迁移、容器启动和核心自动化测试。

### 阶段 2：仓内效率、退货与客户门户
完成波次、分拣、补货、盘点、调拨、退货、异常、打印与货主端。
交付关键设备测试步骤；实机不可用时明确保留验收项。

### 阶段 3：第一个真实 ERP 闭环
以实际取得完整权限、符合用户业务的 ERP 为准，不为了凑数量连接无关服务。
先只读验证，再沙箱读写，再由用户批准小范围真实试运行。
验收链路：订单/商品映射 → 必要面单 → 仓库预占与作业 → 实际交接 → 包裹/状态回传 → 库存对账。
只有库存读取权限的 UpSeller 接口不计入完整履约对接。
没有任何可用完整接口时，保留该阶段为外部阻塞，同时完成标准适配层、官方协议契约测试与其他内部阶段。

### 阶段 4：计费对账与高级业务
完成报价、费用、账单、收款登记、报表；逐步实现 B2B、箱托、平台仓转运与分销配额。
高级模块根据用户业务价值排序；不得把尚未启用的全套高级业务当作首期已交付。

### 阶段 5：生产试运行与扩展
完成权限/安全测试、并发与故障演练、备份恢复、库存初始迁移与对账。
先一仓/一组授权货主试运行，定义唯一库存责任系统与切换截点，避免新旧系统同时独立扣库存。
观察无误后才扩仓与增加 ERP；需明确回退路径且不丢失切换后的真实业务流水。

## 8. 必须通过的测试场景

### 8.1 业务与一致性
- 同一 SKU 入库 100 件，合格上架 100，订单预占 3，拣货/打包期间在库仍为 100，可分配为 97；交接后在库 97、该单预占 0。
- 在库仅 1 件，两个独立并发订单各预占 1，最多一个成功。
- 同一 webhook、扫描提交、worker 消息重复处理 10 次，仅发生一次业务入账和一次对应计费。
- 作业提交成功但客户端未收到响应，再次提交不会创建第二笔收货/发货/收费。
- 2 件合格商品退回，签收后先处于待检；质检通过前不能销售，通过后只加回一次。
- 已拣未交接取消，必须回位/撤销作业后释放；已交接取消不直接恢复库存。
- 多包裹订单其中一个发出时，只扣该包裹数量并保持整单部分履约。
- 调拨发出、在途、部分接收、差异处理前后数量守恒，不双计库存。
- 组合装与组件可售数量一致，分配、拆组和实物组装不能超卖。
- 盘点期间发生合法出库，盘点确认不会抹掉新出库记录。
- 同一 SKU 字符串属于不同货主时，库存和订单绝不串用。
- 修改报价后，历史已确认账单不改变；重试计费和重打面单不重复扣款。

### 8.2 接口、隔离与故障
- 货主 A 通过修改 URL/请求 ID/导出参数/附件链接，不能读取或修改货主 B 数据。
- 过期 token、权限缺失、限流、网络超时、500、回调乱序、重复消息、SKU 映射失败有可解释且可恢复处理。
- 对外建单返回未知结果时，先查询恢复而不是无条件再建单。
- ERP 断连不损坏本地账本；恢复后能补偿同步并对账。
- 服务或 worker 重启后，已承诺处理的任务不丢失，不因重试重复出库。
- API、页面与 worker 都使用相同的服务端授权规则。
- 备份可在独立测试环境成功恢复，并核对库存、订单和附件引用。

### 8.3 界面与运行证据
使用自动化浏览器测试关键业务流程，保存脱敏截图、测试命令与结果。
空状态、加载、权限不足、部分成功、重试与失败状态都要可用；不保留生产可见的空按钮。
中文和巴西葡语关键页面均检查文本溢出、金额、日期、时区和打印布局。
提供明确的性能测试数据集、并发、服务器资源、延迟、错误率和数据库瓶颈，不编造日订单量或承载能力。
测试数据规模可逐步增加；通过小样本不等于通过生产负载验收。
